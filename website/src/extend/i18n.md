# 国际化

::: danger 实现进度 15% · 进行中
没有完整 i18n 实现：locale 注入、语言包注册与 `replaceText` 均未接。正文仅说明当前可用替代方案和未实现契约。
:::

Vamis 当前没有独立 i18n 包。作者写在 schema 里的 `label` / `title` / `body` 按原文渲染；内置日期、校验等文案目前以 zh-CN 为主。不要根据 Amis 的同名文档推断 Vamis 已支持语言切换。

## 当前可用的做法

需要多语言业务文案时，在宿主中先选择语言，再生成对应 schema 或数据。例如把字典放在 `data` 中，通过模板读取：

```schema
type: page
data:
  text:
    title: 表单页面
    name: 名称
body:
  type: form
  body:
    - type: input-text
      name: name
      label: "${text.name}"
```

也可以由宿主直接生成不同语言的 schema，再通过 `updateSchema` 替换。这样不需要把未实现的 locale 注入当作前提。

## 内置组件文案

内部组件文案与 schema 文案是两条通道。当前没有 `registerLocale`、语言包加载或逐 key 回退机制；日期过滤使用内置 zh-CN locale，其它语言与 RTL 布局均未承诺。

下面的 `locale` 只是 Amis 兼容方向，**当前不会更改 Vamis 文案**：

```javascript
// 目标契约，不是当前可运行的国际化示例
vamis.embed('#root', schema, { locale: 'en-US' })
```

`updateProps({ locale })` 当前也不会应用语言。SDK 实际更新能力以 [JS SDK API](/start/sdk#api) 为准。

## 全局文本替换

`env.replaceText` / `replaceTextIgnoreKeys` 当前未接。下面是目标形态，不能用于生产：

```javascript
// 目标契约，当前未实现
vamis.embed('#root', schema, {}, {
  replaceText: { VAMIS_HOST: 'https://maxid.github.io/vamis/' }
})
```

对应 schema 也只作契约展示：

```json
{
  "type": "tpl",
  "tpl": "VAMIS_HOST"
}
```

当前替代方案是在 `parseSchemaText` 之前由宿主做受控替换，或直接生成最终 schema。不要对整棵 schema 做不区分字段的字符串替换，以免误改 `type`、`name`、`target` 等功能字段。

## 按语言覆盖 schema 字段

Amis 的 `{ "en-US": { "label": "username" } }` 覆盖写法当前同样未接。需要此效果时，由宿主显式选择字段后再交给 Vamis：

```javascript
const localized = {
  ...schema,
  label: schema[locale]?.label || schema.label,
}
```

如果未来接入 locale，缺失翻译应回退到原始文案，而不是直接显示语言 key。当前行为就是保留原文。
